# Single-listing materialization and publication

This path consumes committed members of a frozen normalization job. It does not capture MariaDB data, run bundle splitting, or grant public access to raw or canonical evidence.

`materialize_single_batch_v2(job, members, fx_hash)` accepts at most 500 exact raw IDs with their committed proposal hashes and optional source-image receipt hashes. It checks the frozen source hash and the complete retained proposal document. The current accepted normalizer is `authoritative-normalizer-v11-category-bound`. Older proposals require a new reviewed normalization job; silently accepting a changed parser result in an old completed job is forbidden.

Every materialized outcome is retained privately, including review, bundle hold, quarantine, and error. Eligible records preserve the selected original source message without trimming, original poster name, supported watch fields, original price/currency, dated FX evidence, and source-image key. Missing image proof cannot become a public image URL. Public poster IDs are random opaque IDs associated with private exact phone evidence, or a record-specific identity when the contact is absent. Dealer verification, consent and ratings remain a separate existing source-bound join; materialization invents none of them.

`publish_materialized_batch_v2(batch_key, expected_revision, hashes, disposable)` is restricted to the database owner. Ordinary service credentials, authenticated users and anonymous users cannot invoke it. Publication requires a direct release connection and a reviewed statement timeout; prewarming a million-row snapshot must not run through a Vercel request. The function rechecks source/canonical content, rejects conflicting existing source identities, records exact before/after row states and request hashes, and prepares both consumer snapshots before commit. Input counts reconcile to inserted, identical, changed and held outcomes. An identical replay makes no new publication mutation. The explicit disposable mode also requires the disposable schema marker and synthetic source evidence; production mode refuses synthetic evidence.

`rollback_materialized_batch_v2(batch_key, expected_revision)` verifies the current row state against the batch's recorded after-state before restoring prior rows or removing that batch's inserted exposures. Raw, normalized, materialized and mutation evidence remains. Removed dealer links retain a durable rollback outcome and prior private linkage versions. All active pagination traversals expire on rollback; frozen payloads remain private evidence, but old cursors cannot keep exposing withdrawn listings. A fresh pair of snapshots is prepared before commit. Retrying a completed rollback changes nothing.

The disposable test `tools/canary-e2e/verify-publication-batch.cjs` proves transaction isolation with a separate database connection and actual HTTP handlers backed by Supabase/PostgREST. It temporarily adds one explicitly synthetic record to the existing 50 fixtures, checks its source-to-card facts, then restores all original 50 records exactly and verifies old cursor rejection. It also exercises source proof refusal, owner-only permissions, replay, and unsafe rollback refusal. It must never target production.

For historical expansion, use one explicit database transaction for a larger cohort. `stage_publication_cohort_batch_v2` accepts the same bounded batch inputs while deferring snapshot preparation. It reuses the preceding batch's exact transaction-local count instead of rescanning the full canonical table for every small write. `finalize_publication_cohort_v2` requires the complete set of staged batch keys, independently recounts the actual final table, reconciles inserted/identical/changed/held totals, and prepares exactly one pair of snapshots. Commit is refused unless every staged batch is finalized; a write after finalization also refuses commit if it invalidates those snapshots. Cohort state reflects partial and complete rollback of its constituent batches. Ordinary single-batch publication continues to prepare its snapshots immediately.

The disposable cohort test covers omitted finalization for both eligible and held-only batches, incomplete membership, exact final counts, absence of intermediate snapshot copies, post-finalization mutation refusal, replay, and byte-for-byte restoration of the original 50 rows. This removes repeated full snapshot copying from each bounded write. It does not remove the need to verify the production database's available capacity and choose appropriate cohort sizes before rollout.

`create_materialization_workflow_v2` binds a workflow to one completed, reconciled normalization boundary and one fixed verified FX receipt. Its configuration cannot change on replay. `read_materialization_workflow_batch_v2` reads at most 25 ordered members after the database checkpoint. It exposes raw evidence only to the private service worker. `commit_materialization_workflow_batch_v2` checks the exact next IDs/proposal hashes and the expected cursor under a row lock, then atomically persists materialization links, outcome counts, a batch receipt and the new cursor. Competing completions cannot advance twice; exact request retries return the retained result. An interrupted worker leaves no lease that another run must wait to expire.

The worker `tools/mariadb-live/run-frozen-materialization-v2.cjs` requires `WF_MATERIALIZATION_EXECUTE=true`, an existing `WF_MATERIALIZATION_JOB`, and a private `WF_MATERIALIZATION_PROGRESS_FILE`. It performs at most four image probes concurrently within a bounded batch. Staged image receipts survive a lost completion response and can be reused when resuming. A valid source-image key requires a receipt, including failed reachability evidence; a claimed success cannot substitute for source-bound verification. The database derives the stored image outcome. Aggregate progress contains no raw payloads or contacts. The worker invokes neither capture nor publication.

Actual disposable Supabase tests prove changed-config refusal, skipped-probe refusal, concurrent completion, changed-replay refusal, restart between two one-row batches, exact message/poster/image/unknown-date preservation, and no work after completion. A separate nine-row frozen boundary reconciles four eligible, two review, one bundle hold, one quarantine and one error to nine durable materialization links. Held/error outcomes have no public document. These tests retained eleven additional private synthetic raw rows; the public 50 were unchanged.

Research browse admission and durable exclusion decisions are described in `docs/frozen-price-research-admission-v2.md`. The first full-volume admission test exposed a new-snapshot cardinality estimate of one row and nested-loop plans over large materialized sets. Its failure evidence was retained. A forward migration restricts nested-loop selection only inside the private admission function; the separate 1.5-million-row retest is still pending and is not a performance pass.

Remaining release work includes historical publication orchestration, full-scale admission performance, full relevant test classification, final exact disposable browser acceptance, and the separately gated production discovery/canary/rollout. A successful disposable publication test is not production approval or completion.
