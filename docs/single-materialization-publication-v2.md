# Single-listing materialization and publication

This path consumes committed members of a frozen normalization job. It does not capture MariaDB data, run bundle splitting, or grant public access to raw or canonical evidence.

`materialize_single_batch_v2(job, members, fx_hash)` accepts at most 500 exact raw IDs with their committed proposal hashes and optional source-image receipt hashes. It checks the frozen source hash and the complete retained proposal document. The current accepted normalizer is `authoritative-normalizer-v11-category-bound`. Older proposals require a new reviewed normalization job; silently accepting a changed parser result in an old completed job is forbidden.

Every materialized outcome is retained privately, including review, bundle hold, quarantine, and error. Eligible records preserve the selected original source message without trimming, original poster name, supported watch fields, original price/currency, dated FX evidence, and source-image key. Missing image proof cannot become a public image URL. Public poster IDs are random opaque IDs associated with private exact phone evidence, or a record-specific identity when the contact is absent. Dealer verification, consent and ratings remain a separate existing source-bound join; materialization invents none of them.

`publish_materialized_batch_v2(batch_key, expected_revision, hashes, disposable)` is restricted to the database owner. Ordinary service credentials, authenticated users and anonymous users cannot invoke it. Publication requires a direct release connection and a reviewed statement timeout; prewarming a million-row snapshot must not run through a Vercel request. The function rechecks source/canonical content, rejects conflicting existing source identities, records exact before/after row states and request hashes, and prepares both consumer snapshots before commit. Input counts reconcile to inserted, identical, changed and held outcomes. An identical replay makes no new publication mutation. The explicit disposable mode also requires the disposable schema marker and synthetic source evidence; production mode refuses synthetic evidence.

`rollback_materialized_batch_v2(batch_key, expected_revision)` verifies the current row state against the batch's recorded after-state before restoring prior rows or removing that batch's inserted exposures. Raw, normalized, materialized and mutation evidence remains. Removed dealer links retain a durable rollback outcome and prior private linkage versions. All active pagination traversals expire on rollback; frozen payloads remain private evidence, but old cursors cannot keep exposing withdrawn listings. A fresh pair of snapshots is prepared before commit. Retrying a completed rollback changes nothing.

The disposable test `tools/canary-e2e/verify-publication-batch.cjs` proves transaction isolation with a separate database connection and actual HTTP handlers backed by Supabase/PostgREST. It temporarily adds one explicitly synthetic record to the existing 50 fixtures, checks its source-to-card facts, then restores all original 50 records exactly and verifies old cursor rejection. It also exercises source proof refusal, owner-only permissions, replay, and unsafe rollback refusal. It must never target production.

Remaining release work includes bounded historical materialization orchestration, final duplicate/repost admission and outcome reconciliation, full relevant test classification, final exact disposable browser acceptance, and the separately gated production discovery/canary/rollout. A successful disposable publication test is not production approval or completion.
